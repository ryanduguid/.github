# Support

## Bugs and feature requests

Use the affected repository's **Issues** tab. Search existing issues first,
then provide the smallest reproduction you can make with fabricated data. Name
the repository version or commit, your operating system, the command you ran,
the result you expected and the result you received.

Do not attach or paste client, taxpayer, employee, payroll, tenant, credential
or other sensitive data. Replace it with synthetic values that preserve only
the shape needed to reproduce the problem.

## Security vulnerabilities

Do not open a public issue. Use **Security → Report a vulnerability** in the
affected repository and follow its `SECURITY.md`.

## Accounting, tax and legal questions

These repositories provide review aids and examples, not personalised advice
or an accounting engagement. GitHub issues are not a channel for urgent
deadlines, lodgments, payments, payroll decisions, legal advice or client
support. A qualified adviser must review any real-world conclusion and the
current primary sources.

## Response expectations

These are independently maintained open-source projects. There is no service
level agreement or guaranteed response time. Clear, focused reports with a
safe reproduction and current source evidence are the easiest to action.
