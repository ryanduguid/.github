# Support

## Bugs and feature requests

Use the affected repository's **Issues** tab. Search existing issues first,
then provide the smallest reproduction you can make with fabricated data. Name
the repository version or commit, your operating system, the command you ran,
the result you expected and the result you received.

For a wrong rate, threshold, date or rule in a page, guide or skill, use the
content correction form: quote the statement and cite the primary source.

Do not paste client, taxpayer, employee, payroll, tenant, credential or other
sensitive data, or taxpayer identifiers such as tax file numbers. Do not attach
confidential files. Replace real data with synthetic values that preserve only
the shape needed to reproduce the problem.

## Security vulnerabilities

Do not open a public issue. Use **Security → Report a vulnerability** in the
affected repository and follow its `SECURITY.md`. Where that repository's
Security tab offers no **Report a vulnerability** button, `SECURITY.md` gives
the email address to use instead.

## Response expectations

These are independently maintained open source projects. There is no service
level agreement or guaranteed response time. Clear, focused reports with a
safe reproduction and current source evidence are the easiest to action.

Security reports follow the repository's `SECURITY.md` instead, including any
response commitment it makes.

<sub>Not advice: these repositories provide review aids and examples, not tax, accounting, legal or financial advice, and no issue or pull request creates a professional engagement. Requests for advice on a real tax position are declined, and issues are not a channel for deadlines, lodgements, payments, payroll decisions or client support. A qualified adviser must review any real-world conclusion against current primary sources.</sub>
